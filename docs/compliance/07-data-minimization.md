## 적용 범위와 현재 상태

QUANTGEN의 공개 시세·수학 모형 연구와 개인 계좌·질문·메모 처리의 필요성을 구분합니다. Upbit 자산조회는 통화·기준통화·잔액·잠금 금액·평균 매수가·총수량을 반환하고, 연구 흐름은 보유 통화 종목을 공개 시세 API에 보내 파생 원화평가액을 계산합니다. 공개 시세 분석에 이 계좌조회가 항상 필요한 것은 아닙니다. 현재 Flet의 기본 포함값과 네이티브의 기본 OFF는 다릅니다.

규칙 이름·메모·개정 이력, 모의주문·판정·상태는 파일에 남을 수 있습니다. AI의 private 필드명 필터는 자유 입력을 분석해 개인정보를 모두 제거하지 않습니다. KIS 토큰은 로컬 JSON에 저장됩니다. 기본 FICC 캐시 TTL 6시간은 재사용 가능 시점의 기준이며 자동 파기 기능이 아닙니다. 전체 개인정보 삭제는 모의투자 초기화와 별개입니다.

검토한 실행 소스에서 중앙 회원 DB·결제 데이터 수집·연령 확인·광고메일 발송·일반 삭제 경로를 찾지 못했지만 실제 웹 판매·지원·호스팅·백업에서의 수집 여부는 별도 조사해야 합니다.

### 2026-10-31 앱 UI 변경 검토

새 지속 설정은 언어·지역 코드이고 교육 가이드에는 계좌·신원 입력을 추가하지 않았습니다. 교육 ZIP과 선택적으로 추가되는 현지화 연구 HTML은 이용자가 고른 내보내기 사본입니다. 정규 연구 JSON의 항목·식별자는 유지하므로 기존 계좌·메모·외부 AI 최소화 검토는 계속 필요합니다.

검토 범위와 코드 근거는 [코드 사실 기록](FACTS.md)의 앱 UI 변경 절을 참조합니다. 소스·문서의 정합성 검토이며 상태는 `review-required`를 유지합니다.

C형 차트 후속에서 지속 설정에 화면 테마 코드 ui/theme(light/dark)를 추가합니다. 차트 재도색과 배치 변경은 기존 관측값·금융 입력을 유지하며 신규 신원·계좌 항목 수집이 아닙니다.

### 2026-11-02 KIS 차트 처리 범위

새 처리 항목은 선택 자산·종목·거래소·조회기간/주기·봉 수, OHLCV·시세·시장/수신 시각, WebSocket 승인키와 캐시 식별용 인증정보 지문입니다. 차트·체결 대기·종목 마스터와 승인키는 프로세스 메모리에서 처리하며 새 차트 기록 파일이나 브라우저 영구 저장소를 만들지 않습니다. 기존 Bearer 토큰 파일·다른 연구 캐시는 별도입니다. 키·시크릿·승인키·지문은 차트 payload나 원문 오류·보고서·Git에 포함하지 않습니다. 기존 앱 키·시크릿을 승인키 발급에도 사용하고 승인키·구독 종목은 별도 비TLS WebSocket 전송처에 전달합니다. KIS 계좌번호·잔고·주문/암호화 계좌통보 수집은 추가하지 않았습니다.

최대 20페이지·요청 봉 20–500개 등 처리 한계를 두고 Flet은 대기 체결 큐가 넘치면 누락을 표시합니다. 범위 제한은 개인정보 최소화 또는 시세 저장권의 승인 증거가 아닙니다. 승인키 캐시는 서버 주소·인증정보 지문별로 구분하지만 다중 사용자 분리·전송 보호 인증은 아닙니다. 23시간 재사용 기준과 연결 중지를 즉시 파기·원격 철회로 표현하지 않습니다. [연결 구현](../../data/kis_stream.py), [KIS 변경 사실](FACTS.md#kis-market-integration-2026-11-02), [삭제 인벤토리](20-deletion.md)에 따라 공유 서버의 키 분리·로그·실제 보유/파기를 별도 확인합니다.

이 절은 양쪽 소스·문서 검토를 통합한 사실 기록이며 `review-required`와 운영 증빙의 미확정 상태를 유지합니다. 법률 검토·공개 승인·실제 배포 검증이 아닙니다.

### 2026-11-02 Home 시세·Q-SCORE 후속 검토

Home의 고정 국내주식 6개는 예시 시세 목록이며 이용자의 계좌 보유 내역을 조회해 만든 목록이 아닙니다. 현재가 조회와 실시간 목록 연결에 필요한 종목·가격 이력·체결 시각·가격·거래량 및 파생 Q-SCORE를 처리합니다. 계좌번호·잔고·실명·투자성향을 새로 수집하거나 모든 모델·외부 AI를 실행하지 않습니다.

점수는 최소 200개, 최대 최근 252개의 수정 일별 가격을 사용하는 로컬 계산이며 체결을 하루 관측 하나씩 누적하지 않고 당일 잠정 종가를 갱신합니다. 점수·목록·이력의 처리 중 메모리와 기존 토큰 파일·다른 연구 캐시는 구분합니다. Home 이탈의 수신 중지는 전역 승인키 캐시·기존 파일·제공자 기록까지 지운다는 의미가 아닙니다. 시작 시 공개 시세 REST 요청과 이용자 선택에 따른 이력·체결 연결을 처리 대장에 각각 기록해야 합니다.

점수 제어기의 수정 이력 메모리 캐시는 인스턴스별 최대 16종입니다. Home과 별도 차트의 제어기는 각각 중지되며 캐시·최근 점수의 일시 보존을 전체 개인정보 삭제로 설명하지 않습니다.

소스·문서 정합성 검토이며 기존 `review-required`와 공개 준비 `BLOCKED`를 유지합니다. 법률 의견·공개 승인·실제 계정 연결·Windows 수동 검증이 아닙니다.

### 2026-11-02 종목 정보·글꼴 확장 후속

Home은 기존 KIS 현재가 응답에서 PER·EPS·공급자 업종명·상장주수를 추가로 읽습니다. 새 계좌·보유 종목·사용자 투자성향 입력, 조회 endpoint·HTTP 호출, 점수/재무 파일 저장을 추가하지 않습니다. 가격과 같은 응답의 유효한 상장주수를 곱한 산출 시가총액은 원시 HTS 시가총액과 분리합니다. 잘못된 선택 항목은 그 값만 비우고 유효 가격은 보존합니다.

재무항목의 REST 수신 시각을 가격 체결 시각과 따로 유지하고 제공자가 준 재무 기준일이 없으면 미제공으로 기록합니다. 처리 범위 확장은 공개 종목 자료이며 기존 개인 계좌·AI 자유 입력·캐시·토큰의 최소화/보유 검토를 해결한 변경이 아닙니다.

소스·문서 정합성 검토이며 `review-required`와 공개 준비 `BLOCKED`를 유지합니다. [최종 범위와 검증 기록](../product/HOME_COMPACT_REVIEW_20261102.md)을 참조합니다.

### 2026-11-02 네이티브 수신 체결봉·선택 지표 후속

1/10/100틱과 1/5/10/30초 봉은 실제 받은 유효 체결만 모읍니다. 새 주기의 시작 snapshot은 빈 봉 목록이며 선택적 현재가를 과거 체결로 변환하지 않습니다. 누적량으로 중복·역순을 검증하고 같은 초의 서로 다른 체결은 실제 시각과 봉 순서/수신 개수로 구분합니다. 시간 해상도·누락 가격·빈 구간을 만들지 않습니다.

조회 봉 수 이내(최대 500)의 실행 중 snapshot·누적량·봉 순서/개수를 유지하며 새 차트 파일·브라우저 영구 저장·개인 프로필·계좌 입력을 추가하지 않습니다. 자동 재연결 후 새 기준 조회는 명시적 조회당 한 번으로 제한합니다. 중지·이탈은 후속 작업을 해제하지만 기존 인증 캐시·제공자 기록 삭제와 다릅니다.

[실제 지원·20종 영향 검토](../product/CHART_RECEIVED_BARS_REVIEW_20261102.md)를 따릅니다. 기존 `review-required`·공개 준비 `BLOCKED`와 미확정 계약/운영 사실을 유지하며 공개 승인·실계정 검증을 뜻하지 않습니다.

KIS가 응답하지 못할 때 Yahoo Finance에 보내는 요청은 화면에서 고른 종목의 티커·봉 주기·기간뿐입니다. 시도한 공급사는 이름·상태·예외 종류와 미설정 `.env` 변수 **이름**만 화면에 남기며 원문 오류·URL·키 값은 표시·저장하지 않습니다. 응답은 화면 메모리에만 두고 새 저장·내보내기·AI 전송을 추가하지 않습니다.

### 2026-11-04 시장 관심종목·종목 목록·한 종목 화면

지속 설정에 `markets/watchlist`를 추가합니다. 저장 항목은 자산 구분·코드·거래소뿐이고 최대 20개입니다. 종목 이름·가격·조회 결과·검색어는 저장하지 않습니다. 키가 없으면 저장하지 않고 Home 6종목을 보여 주며, 이용자가 종목을 넣거나 뺄 때만 씁니다.

KIS 종목 마스터(`kospi_code`, `kosdaq_code`)는 파일 이름만으로 받고, 원본 줄과 검색 색인을 프로세스 메모리에만 둡니다. 새 파일·캐시 디렉터리를 만들지 않으므로 위 2026-11-02 절의 “종목 마스터는 프로세스 메모리” 원칙을 유지합니다. 한 종목 화면의 현재가·투자자별 매매·공매도 자료도 공개 종목 자료이며 메모리에만 둡니다. 요청에는 종목 코드·날짜와 기존 인증정보만 쓰이며 계좌나 이용자 입력은 보내지 않습니다.

공급자·관측일 칸을 화면에서 뺀 것은 표시 변경입니다. 처리하는 항목은 줄지 않았습니다. 매크로·외환 캐리 표는 열만 숨기므로 보고서 내보내기에 그 열이 그대로 있습니다. KRX 시세의 `source`·`as_of`(KIS가 아닌 대체 시세는 `as_of`를 화면에 보임)와 ETF 시세의 `as_of`도 행을 화면에서만 숨기므로 내보내기에 남습니다. 시장 카드·차트·종목 정보·Home 상세 창에는 내보내기가 없습니다. 글꼴 파일을 읽지 못하면 Python logging 경고에 파일 경로만 남깁니다. 앱이 로그 처리기를 설정하지 않으므로 경고는 표준 오류로 나가고 로그 파일은 생기지 않습니다. [변경 사실](FACTS.md#markets-watchlist-2026-11-04)을 따릅니다.

### 2026-11-10 소유자 UI 검토 14건

Strategy Lab·Portfolio·Quant Lab·Signals·ETF의 데이터 출처 선택 상자를 숨기고 앱이 `load_history(source="best")`로 제공처를 고릅니다([시세 이력](../../core/quant/history.py) `_best_history`, `_yahoo_candidates`). FMP·KIS 키가 있으면 기존 `auto`와 같은 경로이며, 설정된 제공처가 실패하면 다른 제공처로 넘어가지 않고 오류를 표시합니다. 키가 없어 `auto`가 합성 시계열을 돌려줄 때에만 Yahoo Finance에 묻습니다. 보내는 항목은 화면에 입력한 종목 기호(6자리 국내 코드는 `.KS`, 실패하면 `.KQ`; `NAS:AAPL` 형식은 `AAPL`)와 조회 기간뿐이며 키·계좌·질문·메모는 보내지 않습니다. KIS 전용 형식(국내 파생 코드·채권 ISIN·`Y0` 금리)은 Yahoo로 보내지 않습니다. 이전에는 키가 없으면 일반 티커와 6자리 코드를 네트워크 요청 없이 합성 시계열로 계산했으므로(`^`·`=F`·`-USD` 형식과 가상자산 기호는 이전에도 키 없이 요청), 실행 버튼만으로 외부 요청이 생기는 범위가 넓어졌습니다. `auto` 자체의 동작은 바뀌지 않았습니다.

Yahoo 응답은 기존 시세 캐시 규칙에 따라 FICC 캐시 폴더에 `HIST_YFINANCE_<기호>_<일수>.json`으로 저장됩니다. yfinance 라이브러리는 사용자 캐시 폴더의 `py-yfinance/`에 `cookies.db`와 `tkr-tz.db`를 만듭니다(검토 환경 yfinance 1.8.0에서 관측). 두 파일은 조회한 종목 기호를 남기며 캐시 TTL은 다시 쓸지를 정하는 기준일 뿐 파기 기한이 아닙니다([삭제](20-deletion.md) 절). Yahoo도 실패하면 합성 시계열의 설명(note)에 실패 사유가 최대 240자 붙습니다. 이 설명은 화면의 접힌 "제공처 메시지" 영역에만 쓰이며 AI 전송 payload에는 제공처 이름(`sources`)만 들어갑니다.

숨긴 선택 상자, 접힌 원문은 표시 변경이며 처리 항목을 줄이지 않습니다. 분석 패널은 같은 영문 해설을 전송 대상으로 유지하고 한국어 해설은 로컬 표시용입니다. AI payload·보고서·계산값은 바뀌지 않았습니다. 숫자 칸의 천 단위 구분(`number_field`, `parse_number`)은 표시와 해석만 바꿉니다. 검증은 Linux headless Chromium의 Flet 화면 캡처와 오프라인 수용 시험이며, FMP/KIS 키가 없고 FRED/Yahoo가 프록시로 막힌 환경이라 실제 제공처 응답과 실제 Windows 환경은 확인하지 않았습니다. [변경 사실](FACTS.md#owner-ui-review-2026-11-10)을 따르며 `review-required`와 공개 준비 `BLOCKED`를 유지합니다.


### 2026-11-11 네이티브 앱 통일(UI-D1~D4)

소유자 결정으로 네이티브 PyQt 앱이 주력 앱이 되어, 위 절의 `source="best"` 경로가 네이티브 화면에도 적용됩니다. Monte Carlo·Portfolio·Signals·Strategy Lab의 요청 검증이 `best`를 받고([분석](../../core/research/analysis.py), [포트폴리오](../../core/research/portfolio_analysis.py), [시그널](../../core/research/signals_analysis.py), [전략](../../core/research/strategy_analysis.py)) 숨긴 선택 상자의 기본값이 `best`입니다. ETF는 `auto`로 요청한 시세 이력을 `best`로 조회합니다([시장 분석](../../core/research/market_analysis.py) `execute_etf`). 그래서 키가 없는 네이티브 실행도 종목 기호·기간을 Yahoo에 보내고, 위 절과 같은 Yahoo 응답 캐시와 yfinance의 `cookies.db`·`tkr-tz.db`가 생깁니다. Strategy Lab에서 실제 자료로 한 실행은 기존 규칙대로 연구 원장에 시행을 기록합니다(이전 네이티브 기본값 `synthetic`은 원장에 쓰지 않았습니다).

분석 해설의 소제목·글머리표, 천 단위 구분, 앱이 쓰는 자료 메모의 한국어 표시([자료 메모](../../quantgen_desktop/source_notes.py))는 표시만 바꿉니다. 보고서·내보내기·AI payload·계산값은 그대로이며 언어 전환 시험이 이를 확인합니다. [변경 사실](FACTS.md#owner-ui-native-2026-11-11)

## 정책 또는 구현 기준

### 필드 도입 기준

새 필드는 목적, 기능상 필요성, 덜 침해적인 대안, 필수/선택, 법적 근거, 처리 위치·수령자, 보유기간·파기 방법을 승인한 후 추가합니다. 단지 향후 분석에 쓸 수 있다는 이유로 계좌·실명·생년월일·전화번호·IP 원문을 수집하지 않습니다. 시장 데이터·통계 결과도 사용자 식별자와 결합되면 개인정보 여부를 다시 평가합니다.

기본 연구 기능은 개인 계좌 연결 없이 작동하도록 구분합니다. 선택적 자산 분석은 사용자가 요청한 범위만 조회하고 인증 키에는 자산조회 등 최소 권한만 사용합니다. 실제 주문·출금 권한을 요구하지 않습니다. 계좌조회 전 안내·선택·결과 보유 여부와 철회 경로는 [폼 동의 기준](06-form-consent.md)을 적용합니다.

### 보유 및 안전한 진단

운영자는 데이터 종류마다 기간과 기산점을 정합니다. 실행 종료 시 소실, 마지막 사용 후 일정 기간, 이용자 선택 삭제, 법정 보존은 서로 다른 규칙입니다. “필요할 때까지”만 기재하지 않고 만료를 판단할 수 있는 조건·담당자·파기 방식·실패 재처리를 정합니다. 보유기간을 정한 뒤 실제 청소 작업·백업 만료·재복원 후 재삭제를 검증합니다.

보고서·자가점검·CI에는 경로·필드명·상태·해시 등 필요한 메타데이터만 사용하고 실제 `.env`, API 키, 토큰, 사용자 질문, 잔고, 원본 연구 메모, 고객 지원 첨부를 입력하지 않습니다. 해시도 개인 식별과 결합될 수 있으면 필요한 범위와 보유를 검토합니다. 진단 자료를 외부에 제출하기 전 비밀값·원본 식별정보 제거와 최소 범위를 확인합니다.

사용자 PC와 공동 서버에서의 책임·접근 가능 범위를 구분합니다. 기존 `~/.nextgen` 경로가 다른 프로그램과 공유될 수 있으므로, 전체 폴더를 삭제하거나 다른 프로그램의 자료를 승인 없이 수집하지 않습니다. 저장소 백업·내보내기·사람이 복사한 파일은 원본 삭제와 별도로 안내합니다.

## 검증과 변경 시 재검토

- **통과:** 목적 없는 항목이 없고, 선택 기능의 계좌 접근이 분리되며, 저장·로그·내보내기·백업·외부 전송의 최소 범위와 실제 보유·파기 절차가 검증됩니다.
- **차단:** 계좌 키 존재로 자동 자산조회, 필드별 근거·보유기간 부재, 자유 입력 필터의 과장, TTL·초기화를 전체 삭제로 설명, 진단 자료의 비밀·개인정보 포함입니다.
- 데이터 스키마·API 응답·AI·사용자 입력·로그·내보내기·지원·배포 경로·백업·유지보수 도구·신규 의존성이 바뀌면 대장을 재검토합니다.
- 파이프라인의 변경 탐지 후에는 영향을 받는 필드를 사람이 확인하고 문서·구현·운영 증거를 갱신합니다. fingerprint만 새로 만들었다고 최소화 의무를 충족한 것으로 표시하지 않습니다.
