## 적용 범위와 현재 상태

사진의 20번 ‘개인정보 삭제 요청 기능을 추가하기’에 대응한다. 정보주체의 삭제·동의 철회 요청과 이용자 기기에 저장된 자료 정리를 구분하며, 운영자 보유자료·외부 제공자·백업까지 처리 범위를 추적한다.

현재 검토한 실행 코드에는 통합 개인정보 삭제 요청 화면·계정 삭제 엔드포인트·삭제 티켓 시스템을 확인하지 못했다. 이 문서는 운영 절차와 구현·시험 기준이다. 실제 삭제 기능이나 고객지원 수신함이 구축되었다고 선언하지 않는다. 실제 접수 채널 `{{privacy.request_channel}}`과 담당자 `{{privacy.request_owner}}`를 활성화·시험한 뒤 공개한다.

현재 존재하는 `reset_practice()`는 모의 장부·판정 등의 초기화이며, 규칙·과거 이력·토큰·캐시·매크로 기록·수동 내보내기를 모두 지우는 개인정보 삭제 기능이 아니다. 기본 6시간 캐시 TTL은 신선도 판정으로, 파일 자동 삭제 기한이 아니다. `.env`나 환경변수에서 인증정보를 제거해도 제공자에서 발급한 키·토큰이 자동 철회되지 않는다.

### 요청 처리 순서

1. **비공개 접수와 기한 관리.** `{{privacy.request_channel}}`에서 요청을 받고 무작위 접수 ID를 부여한다. 공개 GitHub 이슈·PR·커밋에 요청 원문·이메일·계좌·신분증·토큰을 올리지 않는다. 법령상 처리·통지 기한을 확인하고 기한과 담당자를 기록한다. 내부 목표는 접수 확인 3영업일 이내, 삭제 판단·처리 및 통지 10일 이내로 하되 적용 법정기한이 더 빠르면 그 기한을 따른다. 확인 지연이나 외부 업체 지연을 이유로 기한을 임의 연장하지 않는다.
2. **최소 본인·대리권 확인.** 기존의 인증된 채널과 연결 가능한 최소 식별자로 확인한다. 누구나 입력할 수 있는 이메일 문자열만으로 다른 사람의 정보를 삭제하지 않는다. 일률적으로 주민등록번호·신분증·전체 계좌내역을 요구하지 않는다. 대리인·법정대리인은 필요한 범위에서 자격을 확인하고 부적절한 자료는 추가 보관하지 않는다.
3. **통제 주체와 범위 확정.** 요청자의 기기 자료인지, 운영자가 받은 지원문의인지, 운영자 호스팅 계정·외부 처리자 자료인지 구분한다. 정확한 사용자 식별자·처리 목적·저장 시스템·사본 범위와 요청이 철회·삭제·이용정지 중 무엇인지 기록한다. 운영자가 보유하지 않는 로컬 기기의 삭제를 완료했다고 회신하지 않는다.
4. **보존 의무·진행 작업 판단.** 법정 보존 의무가 있다면 실제 법령·해당 항목·보존 종료일을 특정하고 필요한 최소 자료만 별도 접근 제한 보관한다. ‘감사 목적’ 등의 막연한 이유로 전부 남기지 않는다. 진행 중 모의 엔진·조회·파일 쓰기를 안전하게 중지하여 삭제 뒤 자동 재생성을 방지한다.
5. **경로와 소유권 사전 점검.** 현재 실행 환경의 설정에서 실제 저장 루트를 확인하고 삭제 후보의 목록·범위만 먼저 만든다. 파일 존재·소유·다른 프로그램 공유·심볼릭 링크·정규화한 경로가 허용 범위 안인지 확인한다. 홈 전체, 저장소 전체, `~/.nextgen` 전체, 추정한 경로를 재귀 삭제하지 않는다. 경로가 불명확하거나 공유되어 있으면 삭제를 보류하고 필요한 정보를 확인한다. 사전 목록을 만들기 위해 새로 개인정보 사본을 복제하지 않는다.
6. **승인된 항목만 처리.** 요청자와 확인한 범위의 자료를 삭제·익명화하고, 보존 대상은 분리한다. 일반적인 파일 삭제를 디스크 전체의 복구 불가능한 물리 소거라고 표현하지 않는다. SSD·클라우드·동기화 저장소의 제거 보장은 매체·서비스의 기능과 계약에 따라 기록한다. 실제 인증정보 유출이 의심되면 로컬 파일 삭제와 별도로 제공자 키·토큰을 신속히 철회한다.
7. **외부 제공자·복제·백업 처리.** 운영자 통제 아래의 제공자·사본·검색 인덱스·예약 작업에 삭제 또는 이용정지를 전파하고 접수·완료·실패를 추적한다. 백업 즉시 삭제가 불가능한 경우 적용 근거, 접근 제한, 삭제 예정일 `{{privacy.backup_expiry}}`, 복원 시 삭제 요청 재적용 절차를 기록한다. 백업이나 외부 제공자 처리가 남아 있으면 전체 완료로 회신하지 않는다. 외부 업체의 삭제를 증거 없이 보증하지 않는다.
8. **검증·회신·최소 기록.** 재시작·재조회로 대상이 재생성되지 않는지, 다른 프로그램의 자료와 동결 연구가 손상되지 않았는지 확인한다. 삭제한 원문 대신 대상 분류·처리 시각·검증 결과·담당자·보존 예외·남은 작업만 제한적으로 기록한다. 완전 완료·부분 완료·보존·요청 보완을 구분하여 이유와 후속 문의 경로를 통지한다.

이 절차는 삭제 명령을 자동 실행하지 않는다. 향후 삭제 기능은 범위 미리보기·대상 검증·재인증·취소 가능 단계·완료 결과를 제공하고, 파괴적 작업을 일반 초기화 버튼에 숨기지 않아야 한다. 원장·동결 연구에 개인정보가 포함되었다면 기존 증거를 임의로 덮어쓰지 않고 권리 처리와 무결성을 함께 검토하는 별도 변경 기록을 만든다. Git 이력에 실수로 포함된 개인정보·키는 일반 파일 삭제만으로 없어지지 않으므로 접근 제한·키 철회·이력 정리·복제본 대응을 별도 사건으로 처리한다.
