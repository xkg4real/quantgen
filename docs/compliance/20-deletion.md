## 적용 범위와 현재 상태

사진의 20번 ‘개인정보 삭제 요청 기능을 추가하기’에 대응한다. 정보주체의 삭제·동의 철회 요청과 이용자 기기에 저장된 자료 정리를 구분하며, 운영자 보유자료·외부 제공자·백업까지 처리 범위를 추적한다.

현재 검토한 실행 코드에는 통합 개인정보 삭제 요청 화면·계정 삭제 엔드포인트·삭제 티켓 시스템을 확인하지 못했다. 이 문서는 운영 절차와 구현·시험 기준이다. 실제 삭제 기능이나 고객지원 수신함이 구축되었다고 선언하지 않는다. 실제 접수 채널 `{{privacy.request_channel}}`과 담당자 `{{privacy.request_owner}}`를 활성화·시험한 뒤 공개한다.

현재 존재하는 `reset_practice()`는 모의 장부·판정 등의 초기화이며, 규칙·과거 이력·토큰·캐시·매크로 기록·수동 내보내기를 모두 지우는 개인정보 삭제 기능이 아니다. 기본 6시간 캐시 TTL은 신선도 판정으로, 파일 자동 삭제 기한이 아니다. `.env`나 환경변수에서 인증정보를 제거해도 제공자에서 발급한 키·토큰이 자동 철회되지 않는다.

### 2026-10-31 앱 UI 변경 검토

네이티브 언어·지역 설정과 교육/현지화 보고서 내보내기를 삭제 범위에 추가합니다. QSettings 항목과 사용자가 선택한 파일은 별도 사본이며 모의투자 초기화나 캐시 TTL로 삭제되지 않습니다. 이번 변경으로 전체 삭제 요청·외부 제공자 삭제·자동 파기를 구현했다고 표시하지 않습니다.

검토 범위와 코드 근거는 [코드 사실 기록](FACTS.md)의 앱 UI 변경 절을 참조합니다. 소스·문서의 정합성 검토이며 상태는 `review-required`를 유지합니다.

C형 후속의 ui/theme도 같은 QSettings 선호 설정의 삭제 범위에 포함합니다. 브라우저 앱 테마는 세션 상태이며 모의 장부 초기화로 네이티브 설정이 삭제되는 것으로 안내하지 않습니다.

### 2026-11-02 KIS 시세·승인키 메모리 범위

KIS 차트는 선택 종목·요청 조건·시세 snapshot·대기 체결과 별도 WebSocket 승인키를 프로세스 메모리에서 처리합니다. `_APPROVAL_CACHE`는 실행 서버/기기에서 서버 주소·인증정보 지문별로 구분하며 23시간은 재사용 판정 기준입니다. 기한 후 항목을 즉시 지우는 타이머는 없고 새 발급으로 덮어쓰거나 프로세스 수명이 끝날 때까지 남을 수 있습니다. 새 모듈에는 승인키의 디스크 저장이 없습니다.

연결 중지·구독 해제·화면 이탈·브라우저 세션 종료는 전역 승인키 캐시·남은 snapshot·기존 Bearer 토큰 파일·공급자 로그 삭제나 원격 승인키 철회를 보장하지 않습니다. worker 종료 시 인스턴스 키를 비우는 동작과 전역 캐시 수명을 구분합니다. 실행 프로세스의 살아 있는 메모리 상태 종료·참조 해제를 저장 매체·로그·백업·공급사까지 복구 불가능하게 소거한 증거로 취급하지 않습니다. 기존 `~/.nextgen/kis_token.json`은 별도 대상이며 통합 삭제·원격 철회 기능을 추가한 변경이 아닙니다. 제공자 보존·철회·삭제와 운영 서버 접근/세션 분리는 미완료입니다. [인증·연결 구현](../../data/kis_stream.py), [차트 처리](../../data/kis_workspace.py), [변경 사실](FACTS.md#kis-market-integration-2026-11-02)를 삭제 지도에 포함합니다.

이 절은 양쪽 소스·문서 검토를 통합한 사실 기록이며 `review-required`와 운영 증빙의 미확정 상태를 유지합니다. 법률 검토·공개 승인·실제 배포 검증이 아닙니다.

### 2026-11-02 Home 시세·Q-SCORE 후속 검토

Home 목록·상세 값, 점수용 수정 일별 이력, 마지막으로 수용한 체결 시각·누적량, 파생 점수·수신 대기열은 실행 중 상태로 삭제 범위에 함께 고려합니다. 새 점수 파일·고객 프로필·연구 원장을 쓰는 흐름은 추가하지 않습니다. Home 이탈·중지 후 수신을 끝내고 늦은 콜백을 무시하는 것은 갱신 생명주기 제어이며 모든 메모리 사본의 보안 소거나 외부 제공자 삭제를 뜻하지 않습니다.

기존 KIS Bearer 파일·승인키 전역 캐시·제공자 보관 기록은 별도 대상입니다. 앱 종료·화면 숨김·연결 해제를 통합 개인정보 삭제 또는 원격 키 철회로 안내하지 않으며, 실제 운영의 로그·백업·공유 프로세스 범위는 계속 미확정입니다.

소스·문서 정합성 검토이며 기존 `review-required`와 공개 준비 `BLOCKED`를 유지합니다. 법률 의견·공개 승인·실제 계정 연결·Windows 수동 검증이 아닙니다.

### 2026-11-02 네이티브 수신 체결봉·선택 지표 후속

네이티브 조회로 시작한 구독/5초 조회와 활성 조건 변경의 450ms 예약, 연결 복구 후 한 번의 자동 재동기화는 **수신 중지**·화면 이탈 시 해제합니다. 복귀만으로 재개하지 않습니다. 진행 중인 REST가 이미 제공자에 전달됐을 수 있으므로 중지가 이전 전송 철회는 아닙니다.

실제 수신한 틱/초봉·누적량·순서/체결 개수와 마지막 snapshot은 실행 중 상태이며 중지 후 마지막 표시가 남을 수 있습니다. 새 저장 파일은 추가하지 않습니다. 수신 종료·참조 해제를 기존 Bearer 파일·전역 승인키 캐시·제공자 로그·백업의 삭제나 원격 키 철회로 안내하지 않습니다. 기존 운영별 삭제·보관·접근 분리의 미확정 사항을 유지합니다.

[실제 지원·20종 영향 검토](../product/CHART_RECEIVED_BARS_REVIEW_20261102.md)를 따릅니다. 기존 `review-required`·공개 준비 `BLOCKED`와 미확정 계약/운영 사실을 유지하며 공개 승인·실계정 검증을 뜻하지 않습니다.

### 2026-11-04 시장 관심종목

`markets/watchlist`(관심종목의 자산 구분·코드·거래소, 최대 20개)를 같은 QSettings 선호 설정의 삭제 범위에 넣습니다. 앱 안에서는 카드의 ×나 한 종목 화면의 ★로 종목을 하나씩 뺍니다. 모두 빼면 키는 빈 목록으로 남습니다. 키 자체를 지우면 다음 실행에서 Home 6종목으로 다시 시작합니다. 키를 지우는 앱 안 버튼은 없고 모의 장부 초기화로도 지워지지 않습니다.

KIS 종목 마스터의 원본 줄(`_MASTER_CACHE`)과 검색 색인, 관심종목 카드와 한 종목 화면의 시세·종목 정보는 프로세스 메모리에만 있고 새 파일은 없습니다. 앱을 끄면 사라지지만 보안 소거나 공급자 요청 기록의 삭제를 뜻하지 않습니다. [변경 사실](FACTS.md#markets-watchlist-2026-11-04)을 따릅니다.

### 2026-11-06 AI 응답 미표시·대조 보류

정상 종료가 아닌 AI 응답은 빈 오류 결과로 처리하여 화면·보고서에 부분 응답을 싣지 않습니다. 네이티브 표시에서 URL·비밀정보를 가려 원문과 달라지면 원문 기준 숫자 대조도 표시·내보내기에서 보류하고 그 이유를 기록합니다. 두 조치는 응답 메모리의 보안 소거, 이미 전송한 질문·계산 결과의 철회, 제공자 기록·기존 내보내기 사본의 삭제 기능이 아닙니다. 사용자가 새로 저장한 AI 보고서의 미검증·대조 상태 메타데이터도 내보내기 사본 범위에 포함합니다. [처리 사실](FACTS.md#ai-commentary-guards-2026-11-06)을 반영하며 통합 삭제·제공자 보존/파기의 미완료 상태와 공개 준비 `BLOCKED`는 유지합니다.

### 2026-11-06 A3 인용·클립보드 범위

“알아보기”의 검색어·선택 용어·화면 인용은 창 메모리에 있고 새 파일·QSettings·외부 AI 저장을 추가하지 않습니다. 닫기와 원본 결과/화면 변경은 패널의 인용·검색 문맥을 비웁니다. 같은 행의 새 값이나 같은 크기의 선택 문구 교체도 기존 인용을 무효화하지만 메모리 보안 소거를 보장하지 않습니다. 명시적 복사로 OS 클립보드에 쓴 내용과 이용자가 만든 후속 사본은 패널 닫기로 삭제되지 않습니다.

출처 “상세 정보” 접기는 화면 숨김이며 원래 보고서·AI 입력·자료 삭제가 아닙니다. 기존 통합 삭제·외부 제공자 삭제·백업·운영 범위의 미완료 조건을 유지합니다. [A3 처리 사실](FACTS.md#a3-reading-layout-2026-11-06)을 삭제 범위 지도와 함께 적용합니다.

### 2026-11-10 자동 제공처 선택의 캐시

연구 화면의 `source="best"`가 Yahoo Finance에 물으면 응답이 기존 FICC 캐시 폴더의 `HIST_YFINANCE_<기호>_<일수>.json`에 저장되고, yfinance가 사용자 캐시 폴더의 `py-yfinance/cookies.db`·`tkr-tz.db`를 만듭니다. 둘 다 조회한 종목 기호를 남기는 로컬 파일이며 앱 안의 삭제 기능은 없습니다. 기존 캐시와 같이 사용자가 폴더를 직접 지워야 하며, 이 항목은 삭제 인벤토리의 미구현 상태(`deletion-not-implemented`)에 포함됩니다. [07번](07-data-minimization.md) 절과 [변경 사실](FACTS.md#owner-ui-review-2026-11-10)을 따릅니다.

### 2026-11-11 상장주식수 캐시·새 화면 설정(UI-D7·UI-D8)

시장 순위 목록의 미국 시가총액 계산값을 위해 Yahoo 상장주식수를 같은 FICC 캐시 폴더(`config.ficc_cache_dir()`, 기본 `~/.nextgen/ficc_cache`)에 종목마다 `SHARES_YFINANCE_<기호>.json`으로 저장합니다. 내용은 저장 시각·기호·주식수·주식수 날짜·출처 이름뿐이며, 기호는 저장소에 고정한 미국 종목(ADR 제외 최대 53개)에서 나와 이용자가 입력하거나 고른 종목이 아닙니다. 그래서 개인을 식별하거나 관심 종목을 드러내는 자료로 보지 않습니다. 다만 저장 시각은 그 기기에서 미국 목록을 마지막으로 언제 불러왔는지를 남기므로, 기기 자료 정리 요청에서는 아래 지도의 FICC 캐시 행 범위에 함께 넣습니다. 24시간은 다시 묻지 않는 재사용 기준이고 자동 삭제가 없으며, 앱 안 삭제 기능도 없습니다(`deletion-not-implemented`). `NEXTGEN_FICC_CACHE_TTL`이 0 이하이면 파일을 쓰지 않습니다. 운영자에게 전송되는 경로는 없으므로 운영자 보유 자료 삭제 요청의 대상은 아닙니다. 연구 Home의 큰 차트가 읽는 고정 6개 시장의 응답(제공처가 돌려준 약 2년·650일 분량 전체, 관측 수 400 이름의 캐시)도 기존 규칙대로 같은 폴더에 남을 수 있습니다.

시가총액 열 머리 tooltip은 "상장주식수 출처 {출처}, 하루 보관"이라고 쓰지만, 24시간은 다시 묻지 않는 재사용 기준일 뿐이고 파일은 지워지지 않습니다([목록](../../quantgen_desktop/market_rankings.py) `_cap_heading_tip`, [한국어 문구](../../quantgen_desktop/owner_ui_language/market.py)). 화면 문구가 보관·파기 기간으로 읽힐 수 있으므로(신선도 만료를 파기로 표시하지 않는다는 [제21조 기준](SOURCES.md)), "하루 동안 다시 씀(파일은 남음)"처럼 고치기 전까지 남은 과제로 둡니다. 목록 아래의 "상장주식수는 하루 한 번 갱신합니다"는 재사용 주기를 말하므로 이 문제에 해당하지 않습니다.

새 QSettings 항목 `ui/sidebar_collapsed`, `markets/detail/indicators`, `markets/detail/period`, `markets/detail/sections`, `markets/detail/side`는 화면 선호이며 종목·가격·검색어를 담지 않습니다. 기존 QSettings 항목과 같이 앱 안 삭제 버튼은 없고 모의 장부 초기화로도 지워지지 않습니다. 종목 상세 화면의 "최근 본 종목"(최대 8개)과 순위 목록·시가총액 응답(KIS 현재가상세 응답과 FMP 일괄 시세 포함)은 프로세스 메모리에만 있으며 앱을 끄면 사라지지만, 보안 소거나 제공처 요청 기록의 삭제를 뜻하지 않습니다. ### 2026-11-11 시장 페이지(UI-D10)

### 요청 처리 순서

1. **비공개 접수와 기한 관리.** `{{privacy.request_channel}}`에서 요청을 받고 무작위 접수 ID를 부여한다. 공개 GitHub 이슈·PR·커밋에 요청 원문·이메일·계좌·신분증·토큰을 올리지 않는다. 법령상 처리·통지 기한을 확인하고 기한과 담당자를 기록한다. 내부 목표는 접수 확인 3영업일 이내, 삭제 판단·처리 및 통지 10일 이내로 하되 적용 법정기한이 더 빠르면 그 기한을 따른다. 확인 지연이나 외부 업체 지연을 이유로 기한을 임의 연장하지 않는다.
2. **최소 본인·대리권 확인.** 기존의 인증된 채널과 연결 가능한 최소 식별자로 확인한다. 누구나 입력할 수 있는 이메일 문자열만으로 다른 사람의 정보를 삭제하지 않는다. 일률적으로 주민등록번호·신분증·전체 계좌내역을 요구하지 않는다. 대리인·법정대리인은 필요한 범위에서 자격을 확인하고 부적절한 자료는 추가 보관하지 않는다.
3. **통제 주체와 범위 확정.** 요청자의 기기 자료인지, 운영자가 받은 지원문의인지, 운영자 호스팅 계정·외부 처리자 자료인지 구분한다. 정확한 사용자 식별자·처리 목적·저장 시스템·사본 범위와 요청이 철회·삭제·이용정지 중 무엇인지 기록한다. 운영자가 보유하지 않는 로컬 기기의 삭제를 완료했다고 회신하지 않는다.
4. **보존 의무·진행 작업 판단.** 법정 보존 의무가 있다면 실제 법령·해당 항목·보존 종료일을 특정하고 필요한 최소 자료만 별도 접근 제한 보관한다. ‘감사 목적’ 등의 막연한 이유로 전부 남기지 않는다. 진행 중 모의 엔진·조회·파일 쓰기를 안전하게 중지하여 삭제 뒤 자동 재생성을 방지한다.
5. **경로와 소유권 사전 점검.** 현재 실행 환경의 설정에서 실제 저장 루트를 확인하고 삭제 후보의 목록·범위만 먼저 만든다. 파일 존재·소유·다른 프로그램 공유·심볼릭 링크·정규화한 경로가 허용 범위 안인지 확인한다. 홈 전체, 저장소 전체, `~/.nextgen` 전체, 추정한 경로를 재귀 삭제하지 않는다. 경로가 불명확하거나 공유되어 있으면 삭제를 보류하고 필요한 정보를 확인한다. 사전 목록을 만들기 위해 새로 개인정보 사본을 복제하지 않는다.
6. **승인된 항목만 처리.** 요청자와 확인한 범위의 자료를 삭제·익명화하고, 보존 대상은 분리한다. 일반적인 파일 삭제를 디스크 전체의 복구 불가능한 물리 소거라고 표현하지 않는다. SSD·클라우드·동기화 저장소의 제거 보장은 매체·서비스의 기능과 계약에 따라 기록한다. 실제 인증정보 유출이 의심되면 로컬 파일 삭제와 별도로 제공자 키·토큰을 신속히 철회한다.
7. **외부 제공자·복제·백업 처리.** 운영자 통제 아래의 제공자·사본·검색 인덱스·예약 작업에 삭제 또는 이용정지를 전파하고 접수·완료·실패를 추적한다. 백업 즉시 삭제가 불가능한 경우 적용 근거, 접근 제한, 삭제 예정일 `{{privacy.backup_expiry}}`, 복원 시 삭제 요청 재적용 절차를 기록한다. 백업이나 외부 제공자 처리가 남아 있으면 전체 완료로 회신하지 않는다. 외부 업체의 삭제를 증거 없이 보증하지 않는다.
8. **검증·회신·최소 기록.** 재시작·재조회로 대상이 재생성되지 않는지, 다른 프로그램의 자료와 동결 연구가 손상되지 않았는지 확인한다. 삭제한 원문 대신 대상 분류·처리 시각·검증 결과·담당자·보존 예외·남은 작업만 제한적으로 기록한다. 완전 완료·부분 완료·보존·요청 보완을 구분하여 이유와 후속 문의 경로를 통지한다.

이 절차는 삭제 명령을 자동 실행하지 않는다. 향후 삭제 기능은 범위 미리보기·대상 검증·재인증·취소 가능 단계·완료 결과를 제공하고, 파괴적 작업을 일반 초기화 버튼에 숨기지 않아야 한다. 원장·동결 연구에 개인정보가 포함되었다면 기존 증거를 임의로 덮어쓰지 않고 권리 처리와 무결성을 함께 검토하는 별도 변경 기록을 만든다. Git 이력에 실수로 포함된 개인정보·키는 일반 파일 삭제만으로 없어지지 않으므로 접근 제한·키 철회·이력 정리·복제본 대응을 별도 사건으로 처리한다.
