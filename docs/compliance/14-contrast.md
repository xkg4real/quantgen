# 14. 색상 대비·색상 독립 전달 기준 및 측정 양식

문서 ID: QG-C14 · 버전: 1.8 · 검토일: 2026-11-04 · 상태: review-required

## 적용 범위와 현재 상태

Flet·Qt의 라이트·다크·시스템 테마, 차트, 포커스·입력 경계, 오류·성공 상태 및 내보낸 문서에 적용한다. `core/theme.py`가 공통 팔레트를 제공하지만 실제 렌더링에는 투명도·그래프·별도 색상·상태 스타일도 있으므로 팔레트 검사만으로 전체 화면을 통과시키지 않는다.

2026-10-31 소스의 sRGB 값을 WCAG 상대휘도 공식으로 계산한 일부 결과:

| 테마 | 전경 / 배경 토큰 | 대비비 | 해석 |
|---|---|---:|---|
| LIGHT | text / bg | 13.87:1 | 해당 불투명 일반 텍스트 조합은 4.5:1 이상 |
| LIGHT | muted / surface_2 | 4.69:1 | 여유가 작아 상태·투명도 변경 시 재측정 |
| LIGHT | error / surface | 5.15:1 | 해당 불투명 일반 텍스트 조합은 4.5:1 이상 |
| DARK | muted / surface_2 | 6.93:1 | 해당 불투명 일반 텍스트 조합은 4.5:1 이상 |
| DARK | error / surface | 7.22:1 | 실제 배경과 투명도 확인 필요 |
| LIGHT | border / surface | 1.28:1 | 필요한 입력 경계를 이것만으로 식별하면 재검토 필요 |
| DARK | border / surface | 1.65:1 | 필요한 입력 경계를 이것만으로 식별하면 재검토 필요 |

Qt의 버튼·텍스트 입력은 `border` 토큰을 사용한다. 포커스에는 `accent` 테두리를 쓰는 선택자가 있지만 모든 제어 유형의 포커스가 검증된 것은 아니다. 위 결과는 특정 소스 조합의 측정이며 실제 앱의 접근성 인증이 아니다.

> 2026-11-11 정정: 네이티브 앱의 버튼·입력 칸·선택 상자·숫자 상자 테두리는 이제 `border`가 아니라 `border`와 `bg`의 중간색입니다(LIGHT `#ECECE6`, DARK `#223028`; `surface`와 1.18:1). 위 표의 `border / surface` 값보다 낮습니다. 아래 “2026-11-11 옅은 구획선·순위 목록·종목 상세 화면” 절을 참조합니다.

옵션 검사 요약은 미실행을 `NOT_RUN`, 한쪽 검사만 가능하면 `PARTIAL`로 표시하고 중립적인 `muted`·`text` 토큰을 사용한다. 이 화면 변경에서도 실제 배경·상태별 대비와 텍스트 표시를 재확인해야 하며, 녹색 0을 제거한 것만으로 접근성 전체 통과로 기록하지 않는다. [검사 상태 코드](../../core/research/quote_coverage.py)와 [Flet 화면](../../ui/derivatives_page.py)을 함께 검토한다. 2026-11-04부터 GBM 헤지 평균 타일은 부호와 무관하게 기본 `text` 토큰이다(기대값이 정의상 0, §10 M4-N7). GARCH-t의 녹색·빨강 표시는 그대로이며 실제 화면 대비는 미재확인이다.

### 2026-10-31 앱 UI 변경 검토

지표별 고정색을 선택 버튼·차트·설명에 공유하고 문자 A–E·선택 체크·실선/점선으로도 구분합니다. Qt SVG의 불완전 배경과 넓은 차트 커서 좌표를 수정했으며 라이트·다크/150% 캡처와 배경 픽셀 검사를 수행했습니다. 이 검사를 전체 대비·포커스·모든 상태 적합성 인증으로 해석하지 않습니다.

검토 범위와 코드 근거는 [코드 사실 기록](FACTS.md)의 앱 UI 변경 절을 참조합니다. 소스·문서의 정합성 검토이며 상태는 `review-required`를 유지합니다.

C형 후속에서 DARK를 QUANTGEN의 숲색 계열로 조정하여 위 대비값을 다시 계산했습니다. 지표별 고정색은 유지합니다. 실제 Qt 및 로컬 Chromium의 라이트·다크 화면을 확인했으며 표의 일부 쌍만으로 전체 색상 접근성을 인증하지 않습니다.

### 2026-11-02 KIS 차트 대비 수정 이력

PR #56 통합 기준 `147afc0`의 [공통 SVG](../../core/market/presentation.py)는 밝은 배경 `#FFFFFF` 위 10px SMA20 범례에 `#C58C23`(2.93724:1), 볼린저밴드 범례에 `#2E9F91`(3.23860:1)을 사용했습니다. 일반 텍스트 4.5:1에 미달했고 금색 그래픽도 3:1에 미달했습니다. `853de90`의 중간 수정은 각각 `#946A1B`/`#247E73`로 기준을 충족했으며, PR #57 통합에서는 더 짙은 다음 팔레트를 최종 보존했습니다. 시장 SVG는 `core/theme.py`와 별도 렌더러 팔레트를 사용합니다.

PR #57의 네 불투명 범례쌍 계산에 더해, 최종 통합의 `tests.market_core_acceptance` 17개 합성 검사는 양 테마·420/1000 폭의 렌더링 텍스트가 4.5:1 이상, 지표 그래픽이 3:1 이상임을 확인하고 색상 외 구조·좌표·지표의 불변을 대조했습니다. 어두운 테마 색상은 유지했습니다.

이는 지정 SVG 색상·배경 조합의 소스/합성 렌더링 검사입니다. 캔들·실제 알파 합성·포커스·선택/오류·비활성·확대·Windows/브라우저·보조기술과 전 화면 대비 수용으로 확대하지 않습니다. [시장 차트 검사](../../tests/market_core_acceptance.py)와 [현재 범위](../product/KIS_MARKET_CHARTS_2026-11-02.md)를 함께 보관합니다.

이 절은 양쪽 소스·문서 검토를 통합한 사실 기록이며 `review-required`와 운영 증빙의 미확정 상태를 유지합니다. 법률 검토·공개 승인·실제 배포 검증이 아닙니다.

### 2026-11-02 Home 시세·Q-SCORE 후속 검토

### 2026-11-02 네이티브 수신 체결봉·선택 지표 후속

지표 가족별 색상을 선택 버튼의 표식·범례·곡선에 연결하고 두 EMA 및 MACD/신호선은 실선·점선으로 구분합니다. 선택 상태·이름·수치·해석 문구가 있어 색상만으로 의미를 전하지 않습니다. 기존 C형 라이트/다크 및 PR61의 실제 세 굵기 글꼴은 보존합니다.

복구본의 실제 SVG 팔레트10쌍을 #FFFFFF(밝게)/#17211E(어둡게) 배경으로 계산한 결과 최소5.095:1입니다. 이 값은 SVG 지표 표식·범례·곡선 색상에 한정하며 선택 버튼·전체 UI의 수용 근거가 아닙니다. 이전 범례 색상 네 쌍의 수치를 새 전체 UI 대비 근거로 전용하지 않습니다. 복수 지표·좁은 화면·테마/언어 전환 후 그래프/읽기 영역의 높이 겹침 회귀는 지정 오프스크린 조건에서 통과했습니다. 초점·확대·전체 접근성 수용을 이 결과만으로 대신하지 않습니다. 실제 Windows 확대·DPI·보조기술과 배포 브라우저는 소스 검사만으로 통과시키지 않습니다.

[실제 지원·20종 영향 검토](../product/CHART_RECEIVED_BARS_REVIEW_20261102.md)를 따릅니다. 기존 `review-required`·공개 준비 `BLOCKED`와 미확정 계약/운영 사실을 유지하며 공개 승인·실계정 검증을 뜻하지 않습니다.

### 2026-11-03 네이티브 가이드 검색 전환

네이티브 기술지표 가이드의 A–E 선택 버튼과 체크 표시를 검색창·추천 목록·선택 칩으로 바꿉니다. 차트에 표시 중인 지표는 칩마다 지표 고정색 왼쪽 테두리와 문자(A–E)·약어를 표시하고 옆에 `×` 제거 버튼(2026-11-04에 동봉 글꼴에 있는 U+00D7로 바꿈)을 두므로 색만으로 구분하지 않습니다. 추천 목록의 선택 행은 기존 `accent_soft` 배경과 본문 `text` 색을 쓰고 분류는 기존 `muted` 캡션 토큰을 씁니다. 라이트·다크·1360/1000px 화면 캡처로 배치를 확인했으며 새 색상 토큰은 추가하지 않았습니다. 대비 수치를 새로 측정한 것은 아니며 전체 대비·포커스 적합성 인증으로 해석하지 않습니다. Flet 가이드는 기존 버튼 방식을 유지합니다.

## 정책 또는 구현 기준

1. 일반 텍스트와 텍스트 이미지는 배경에 대해 최소 4.5:1을 목표 수용 기준으로 한다. WCAG의 큰 텍스트 정의를 실제 글꼴 크기·굵기와 단위로 입증한 경우에만 3:1 기준을 적용한다. 단순히 제목이라는 이유로 기준을 낮추지 않는다.
2. 제어를 식별하는 데 필요한 경계·상태 표시와 의미 있는 그래픽 요소는 인접 색상에 대해 최소 3:1을 점검한다. 장식 구분선에 무조건 같은 기준을 적용하거나, 필요한 제어 경계를 장식으로 분류하지 않는다.
3. 색상만으로 양수·음수·통과·실패·오래된 데이터·선택 상태를 전달하지 않는다. 부호·숫자·텍스트·모양·선 스타일 중 적절한 수단을 함께 사용한다.
4. 실제 합성된 색상을 계산한다. 투명한 색·음영·호버·선택·비활성·차트 배경을 원래 HEX 값만으로 판정하지 않는다. WCAG 예외를 적용하면 요소와 이유를 기록한다.
5. 포커스는 배경과 구별되고 가려지지 않아야 한다. 대비 측정 외에 [15번 키보드 점검](15-keyboard.md)에서 위치·지속성·도달 가능성을 검증한다.
6. 라이트·다크를 모두 검사하고, 시스템 테마를 지원하는 Flet은 실제 OS 모드 전환도 확인한다. 확대·고대비 설정에서 오류·선택 상태를 구별할 수 있어야 한다.

측정 공식은 WCAG의 sRGB 선형화와 상대휘도를 사용한다. 대비비는 `(밝은 상대휘도 + 0.05) / (어두운 상대휘도 + 0.05)`이며, 반올림 표시가 기준을 넘더라도 원래 계산값이 기준 미만이면 통과가 아니다.

## 검증과 변경 시 재검토

- **통과:** 실제 필요한 전경·배경 조합이 해당 기준을 충족하고, 색상 외에도 의미와 상태를 이해할 수 있으며, 모든 지원 테마·필수 상태의 증거가 있다.
- **실패:** 일반 텍스트 기준 미달, 필요한 제어·그래픽 식별 실패, 색상만으로 중요한 상태를 전달한다. 기준 미달 조합을 전체 평균으로 상쇄하지 않는다.
- **미실행:** 토큰만 검사했거나 실제 화면·알파 합성·필수 상태를 확인하지 못했다. 접근성 자동 검사 결과는 수동 검증과 별도 기록한다.
- `core/theme.py`, Qt 스타일시트, Flet 구성요소, 차트 색상·투명도·범례, 글꼴 크기·테마 처리 변경 시 영향을 받은 모든 쌍을 재측정한다. 변경 없는 측정값도 기준 소스 커밋과 연결한다.
