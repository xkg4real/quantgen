- 작성: DIDM_DEV 세션, 2026-11-24. 코드: `core/didm/models/confirmation.py`, `core/didm/models/surprise.py`. 시험: `tests/didm_confirmation_acceptance.py` (합성 수익률만; 실제 가격·네트워크·시계 없음).
- 규칙은 `docs/didm/PREREG_V0.md` 4절 (동결, 소유자 승인 P3)이고 이 문서는 그것을 코드로 옮긴 방법만 적습니다. 숫자는 코드 상수이고 시험이 사전등록 문구와 대조합니다.
- 결과는 레코드의 `market_confirmation` 표지일 뿐입니다. 시장 반응이 판단과 어긋나도 매수·매도 신호로 바꾸지 않습니다 (사전등록 4절 근거 칸).

## 1. 규칙 → 코드

| 사전등록 4절 | 코드 |
|---|---|
| 기대 반응: 사건 전 [−125, −6] 거래일 120일로 r_i = α + β·r_m | `fit_market_model` (최소제곱, 잔차 표준편차는 자유도 n − 2) |
| 사건 창: 기업 [0, +1] 거래일 | `confirm_daily` |
| 거시: 일중 자료가 있으면 [0, +60분], 없으면 [0, +1] 거래일 | `confirm_intraday` / `confirm_daily` |
| \|CAR[−5, −1]\| > 2σ·√5이고 같은 방향 → ALREADY_PRICED (먼저 판정) | `decide` 첫 단계 |
| 예측 방향과 같고 \|AR\| > 2σ (창 길이에 맞춰 √n배) → CONFIRMED | 이틀 창이면 문턱 2σ·√2 |
| 반대 방향 \|AR\| > 2σ → CONTRADICTED | 같은 문턱 |
| 창이 안 끝났거나 나머지 → PENDING | 호출자가 `last_known_index`로 "지금 아는 마지막 날"을 주고, 그 뒤 자료는 배열에 있어도 읽지 않음 |
| Kalshi 거래량 1,000계약 미만 → `liquid = false`, 신호·충격에서 뺌 | `surprise.is_liquid`, `probability_move` (얇은 시장의 확률 변화는 None) |
| 컨센서스가 있으면 (발표치 − 컨센서스) / 과거 표준편차, 없으면 "미상" + 확률 변화 | `surprise.macro_surprise` |

## 2. 문구에 없어서 이 세션이 정한 것 (소유자 확인 대상)

| # | 무엇 | 고른 것 | 다른 선택지 |
|---|---|---|---|
| M1 | ALREADY_PRICED를 언제 판정하나 | 사건 전 5일만으로 판정. 사건 창이 아직 안 끝났어도 "먼저 판정" | 사건 창이 끝난 뒤에만 판정 (그 전에는 PENDING) |
| M2 | 중립 예측 (방향 0) | 확인·반박 대상이 아니므로 언제나 PENDING | — |
| M3 | 추정 창 120일이 다 없을 때 (신규 상장, 결측) | PENDING과 이유. 짧은 창으로 대신 추정하지 않음 | 최소 일수 (예: 60일)를 정해 허용 |
| M4 | 일중 규칙의 σ | 과거 같은 길이 (60분) 창 움직임의 표준편차, 최소 20개 | 일별 잔차 σ를 시간 비율로 환산 |
| M5 | "과거 표준편차" | 같은 지표의 **과거 서프라이즈** (발표치 − 컨센서스)의 표본 표준편차, 이번 발표 전 것만, 최소 8개. 모자라면 "미상" | 발표치 자체의 표준편차 |
| M6 | 문턱 비교 | 엄격한 부등호 (>) 그대로. 정확히 2σ면 PENDING | — |
| M7 | 거시 대상의 기대 반응 | 일별 규칙은 기업과 같은 시장 모형을 씀 (호출자가 대상 자산과 지수를 줌). 지수 자체가 대상이면 호출자가 무엇을 "시장"으로 줄지 정해야 함 | 평균 조정 수익률 |

M1과 M5는 판정이 달라질 수 있어 설정값 (`confirmation.ConfirmationConfig.already_priced`, `surprise.SurpriseConfig.scale`·`min_history`)으로 두었고, 선택지별 결과는 `PREREG_V0_1_PROPOSAL_2026-11-24.md` 10절에 있습니다 (소유자 질문 10·11). 기본값은 위 표의 "고른 것"입니다. M7은 실제 자료를 붙일 때 다시 봐야 합니다 (미결).

## 3. 자료는 호출자가 줍니다

이 모듈은 가격 출처를 import하지 않습니다 (`core/**`는 `data.didm`을 import할 수 없음). 수익률 배열, 발표치, 컨센서스, 확률, 거래량을 모두 인자로 받습니다. 시점 규칙 (그 시각에 알 수 있던 값만)은 호출자가 저장소의 `as_of()`로 지키고, 이 모듈은 `last_known_index` 뒤를 읽지 않는 것으로 한 번 더 막습니다.

## 3.1 판정을 쌓는 곁기록 `didm-confirmation-v0` (DIDM-8/a)

레코드는 조립할 때 굳고, 그때는 사건 창이 끝났을 수 없어 `market_confirmation`이 언제나 PENDING입니다. 판정은 며칠 뒤에 나옵니다. 레코드를 고치지 않고 판정을 **덧붙이기 전용 곁기록**에 쌓습니다 (`core/didm/models/confirmation_log.py`).

| 필드 | 뜻 |
|---|---|
| `schema` | `didm-confirmation-v0` |
| `record_id` | 어느 레코드의 판정인가 |
| `judgement_sha256` | 그 레코드를 만든 판단의 해시 (검증 표식). 같은 레코드에 다른 판단의 판정이 섞이면 거부 |
| `status` | CONFIRMED / CONTRADICTED / ALREADY_PRICED / PENDING |
| `known_at` | 그 판정을 **알게 된 시각** (시간대 필수) |
| `rule_version` | 판정 규칙의 판 (`conf-rule-…`): 등록 숫자와 고른 해석 (`ConfirmationConfig`)의 해시 |
| `window` | 쓴 창: `{kind: daily, first: 0, last: 1}` 또는 `{kind: intraday, first: 0, last: 60}` |

- **읽는 규칙:** `as_of(곁기록, record_id, 결정 시각)`은 `known_at ≤ 결정 시각`인 줄 중 마지막 것만 돌려줍니다. 아직 아무것도 모르면 PENDING입니다. 나중에 알게 된 판정은 곁기록에 이미 들어 있어도 앞선 결정에서는 보이지 않습니다.
- **덧붙이기 규칙:** 앞 줄은 바뀌지 않습니다. 같은 레코드에서 더 이른 `known_at`의 줄, 같은 규칙 판에서 확정 판정을 바꾸는 줄은 거부합니다. 규칙 판이 다르면 (해석을 바꿔 다시 판정) 새 줄로 쌓이고, 읽을 때 규칙 판을 골라 읽을 수 있습니다.
- **파일은 열지 않습니다.** `dumps`/`loads`가 한 줄 JSON을 주고받고, 어디에 쌓을지는 호출자 몫입니다. 저장 위치는 시점 저장소 규칙에 맞춰야 하며 메인이 DATA_SOURCE와 조율합니다 (미정).
- 끝에서 끝까지 실행 (`pipeline.confirmation_entries`)은 기사를 받은 때 PENDING 한 줄, 그 뒤 결정 시각마다 등록 규칙을 다시 적용해 판정이 바뀔 때만 한 줄을 더합니다. 시험: 곁기록의 판정이 "그 결정 시각까지의 수익률만 잘라서 다시 판정한 것"과 같고, 한 결정 앞에서는 보이지 않으며, 충격은 곁기록과 무관합니다.
