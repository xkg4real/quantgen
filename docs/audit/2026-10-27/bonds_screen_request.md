## QUANTGEN Bonds 화면 테스트 기반
구현 검증 및 수정 요청서
대상: Bonds > Calculator & risk / Scenarios / Futures hedge

### 1. 목적 및 검증 범위
이 문서는 실제 QUANTGEN Bonds 화면에서 수행한 수동 입력 테스트와 화면에 표시된 결과를 바탕으로, 해당 기능을 구현한 AI가 계산 로직·입력 검증·UI 상태 관리·표시 수치의 일관성을 독립적으로 재검토하도록 요청하기 위한 문서다.
중요: 화면에서 관찰한 사실과 아직 검증되지 않은 의심 사항을 구분한다. 현재까지의 화면 테스트만으로 금융 계산식의 정확성, 외부 데이터의 진위, 전체 코드의 안정성이 입증된 것은 아니다. 아래 관찰값을 정답으로 간주하지 말고 코드와 독립적인 기준 계산으로 확인할 것.

### 2. 화면 테스트에서 관찰한 사실

#### 2.1 기본 계산기 입력/출력
화면에서 확인한 입력 항목: Coupon %, Maturity (years), Coupons / year, Price (per 100), Yield %, Notional, Curve source. Coupon 주기는 Semi-annual로 표시되며, 결과 카드에는 Price, Yield, Macaulay, Modified, Convexity, DV01, z-spread, Carry (3m), Roll-down, Carry + roll, Breakeven 등이 표시된다.
관찰된 입력·결과 예시:
| 입력 조건 | 표시된 가격/수익률 | 주요 위험 지표 | 비고 |
|---|---|---|---|
| 쿠폰 5.5%, 만기 10년, YTM 4.5%, 가격 입력 100 | 가격 107.982 / YTM 4.500% | Macaulay 7.92y, Modified 7.74, Convexity 73.0, DV01 836 | 화면 캡처 중 하나 |
| 쿠폰 4.5%, 만기 10년, YTM 5.5%, 가격 입력 100 | 가격 92.386 / YTM 5.500% | Macaulay 8.07y, Modified 7.86, Convexity 74.4, DV01 726 | 화면 캡처 중 하나 |
| 쿠폰 5.5%, 만기 10년, YTM 5.5%, 가격 입력 100 | 가격 100.000 / YTM 5.500% | Macaulay 7.82y, Modified 7.61, Convexity 71.2, DV01 761 | 액면가와 YTM 일치 사례 |
| 쿠폰 5.5%, 만기 10년, 가격 입력 95 | 가격 95.000 / 계산 YTM 6.178% | Macaulay 7.76y, Modified 7.52, Convexity 69.9, DV01 715 | 가격에서 YTM을 역산 |
| 쿠폰 5.5%, 만기 10년, 가격 입력 105 | 가격 105.000 / 계산 YTM 4.863% | Macaulay 7.88y, Modified 7.70, Convexity 72.3, DV01 808 | 가격에서 YTM을 역산 |


#### 2.2 입력 검증 오류 재현
가격(Price per 100)과 Yield % 필드에 동시에 값이 존재하는 상태에서 Run을 누르면 “Give exactly one of price or ytm.” 오류가 표시되었다. 예를 들어 Price=100과 Yield=4.5 또는 Price=105와 Yield=4.5가 동시에 입력된 화면에서 오류가 재현되었다.
이 오류 메시지 자체는 가격 또는 YTM 중 하나만 지정해야 한다는 입력 계약을 나타내는 것으로 보인다. 그러나 사용자가 값을 입력·수정할 때 두 필드를 어떻게 비우거나 비활성화해야 하는지 UI가 명확하게 안내하는지, 빈 값과 숫자 0을 구분하는지, 이전 실행 결과가 오류 이후에도 남아 혼동을 주는지는 추가 검토가 필요하다.

#### 2.3 Scenarios 화면
Scenarios 도구에서 쿠폰 5.5%, 만기 10년, 반기 쿠폰, YTM 4.5%, 명목금액 1,000,000 조건의 화면에 기준 가격 107.982, +100bp parallel 손익 -81,597, -100bp parallel 손익 +89,400이 표시되었다.
동일하게 쿠폰 5.5%, 만기 10년, YTM 5.5%, 명목금액 1,000,000으로 실행했을 때 기준 가격 100.000, +100bp parallel 손익 -74,657, -100bp parallel 손익 +81,766이 표시되었다. 다른 시나리오로 +25bp -19,305, -25bp +19,748, bear steepener -9,888, bull steepener +27,819, bear flattener -26,977 등이 화면에 나타났다.
관찰상 YTM 변경 후 기준 가격 및 시나리오 손익이 달라졌다. 금리 상승 시 손실, 금리 하락 시 이익이라는 방향성은 일반적인 고정금리 채권과 부합한다. 단, 이것은 정성적 일관성만 확인한 것이며 실제 손익 숫자가 정확하다는 증거는 아니다.

#### 2.4 Futures hedge 화면
Futures hedge 도구에서 기준 가격 100.000, YTM 4.500%, 명목금액 1,000,000, Position DV01 798, CTD DV01/contract 65, Conversion factor 0.8000일 때 Futures DV01 81.25, Contracts to sell 9.82, Rounded 10으로 표시되었다. 설명 문구에는 contracts = position DV01 × CF / CTD DV01 = 798 × 0.8000 / 65.00 = 9.82로 표시되었다.
산술식은 표시된 입력값에 대해 약 9.82가 맞다. 다만 선물 계약의 DV01 정의, CTD 및 conversion factor 처리, 롱/숏 포지션 부호, 반올림 후 잔여 DV01 계산, 실제 계약 명목 및 인도 옵션 등은 별도 검증 대상이다.

### 3. 구현 AI에게 반드시 검토시킬 항목

#### A. 가격–YTM 입력 계약 및 UI
- Price와 YTM 중 정확히 하나만 입력되도록 하는 조건을 코드에서 확인한다.
- 빈 문자열, 공백, None, 숫자 0, 음수, NaN/Inf가 각각 어떻게 처리되는지 확인한다. 특히 0% YTM은 유효 입력일 수 있으므로 ‘값이 0’이라는 이유만으로 빈 값처럼 취급하지 않는다.
- 사용자가 Price 모드와 YTM 모드를 명시적으로 선택하도록 하거나, 한 필드 입력 시 다른 필드를 자동으로 비우는 등 모호하지 않은 UX를 제안한다.
- 검증 실패 시 이전 실행 결과가 새 입력값의 결과인 것처럼 남지 않게 하고, 필드별 오류를 표시한다.
- Calculator, Scenarios, Futures hedge 도구 전환 시 입력 상태가 의도치 않게 공유·잔존되는지 테스트한다.

#### B. 채권 가격 및 위험 지표 계산
- 반기 쿠폰 지급 기준 가격 공식과 YTM 복리 주기, 연간 쿠폰율 변환이 일관되는지 확인한다.
- Macaulay duration, modified duration, convexity, DV01의 정의·단위·스케일을 코드와 독립 계산으로 대조한다.
- 가격 100일 때 쿠폰율=YTM이면 가격이 100이 되는지, 쿠폰율>YTM이면 가격이 100보다 큰지, 쿠폰율<YTM이면 가격이 100보다 작은지 테스트한다.
- 가격 입력 95 및 105에서 역산한 YTM이 독립적인 수치해법과 일치하는지 확인한다.
- 만기 0/음수, 쿠폰 0, 쿠폰 빈도 1/2/4/12, 극단적인 수익률, 매우 작은 가격 등 경계 조건을 테스트한다.
- 현금흐름 날짜, 정산일, 경과이자, day-count convention, 상환 시점이 단순 모델에서 생략되었다면 UI와 문서에 그 한계를 명시한다.

#### C. 시나리오 손익(Full revaluation)
- 각 시나리오에서 금리곡선을 어떻게 평행 이동하거나 비틀어(st steepener/flattener) 재구성하는지 수식과 코드 위치를 제시한다.
- ‘z-spread held’가 실제로 시나리오 재평가에 반영되는지 확인한다. 평행 이동 전후 할인곡선 및 z-spread 적용 순서를 설명한다.
- 기준 가격과 시나리오별 재평가 가격을 각각 출력하고, P&L = (scenario price − base price) × notional / 100인지 확인한다.
- YTM 4.5%와 5.5% 테스트에서 화면의 +25bp, -25bp, +100bp, -100bp 손익을 독립적인 계산으로 재현한다.
- 평행 금리 상승의 손실과 하락의 이익이 기본적으로 성립하는지, convexity로 인해 상승·하락 손익이 대칭이 아닌 이유가 합리적인지 확인한다.
- 시나리오 이름(예: bear steepener, bull flattener)과 장단기 금리 변화의 부호가 업계 통상 정의에 맞는지 명시한다.
- 시나리오 손익 퍼센트의 분모가 현재 시장가치인지 명목금액인지 확인하고 레이블 또는 설명에 명시한다.

#### D. Treasury futures hedge
- 계약 수 공식 position DV01 × conversion factor / CTD DV01의 적용 조건을 검토하고, 계약 DV01 및 CF 정의를 문서화한다.
- 롱/숏 채권 포지션에 따른 선물 매수/매도 방향이 정확한지 테스트한다.
- 계약 수를 반올림 또는 올림/내림했을 때 잔여 DV01을 실제 계산하고, 화면 설명과 일치하는지 확인한다.
- Position DV01 공란 시 자동 계산되는 값이 어떤 포지션·명목금액 기준인지 확인한다.
- CTD DV01 0/음수, CF 0/음수, 공란·문자 입력을 방어한다.
- 실제 Treasury futures는 CTD 변경, basis, delivery option, invoice price 등이 존재하므로 현재 계산기가 단순 DV01 hedge 근사치라면 이를 명시한다.

#### E. Curve source 및 데이터 신뢰성
- Auto(FRED, else synthetic)에서 실제 FRED 데이터와 synthetic fallback을 구분해서 표시하는지 확인한다.
- FRED 호출 실패·빈 데이터·오래된 데이터일 때 synthetic 결과를 실데이터처럼 표시하지 않는지 확인한다.
- Curve as-of 날짜가 실제 관측일인지, 다운로드 날짜인지, 계산 기준일인지 확인하고 이름을 분명히 한다.
- 곡선의 만기별 값, 보간 방식, 단위(%/decimal), 할인인자 변환을 기록하고 입력 데이터가 없거나 이상할 때 fail-safe 처리한다.
- 시나리오가 synthetic curve에서도 실행된다면 데이터 출처와 결과의 제한을 화면에서 명확히 알린다.

#### F. 성능·상태 관리·재현성
- Run 한 번당 실제 계산시간을 측정하고, 데이터 요청시간과 계산시간을 분리해서 기록한다.
- 같은 입력·같은 데이터 스냅샷으로 재실행했을 때 결과가 재현되는지 확인한다.
- 곡선 데이터 캐싱 및 중복 API 호출 여부를 확인한다.
- 모든 결과 카드, 차트 제목/범례, Analysis 설명이 동일한 기준 입력값과 같은 계산 결과를 사용하는지 검증한다.
- 사용자 입력을 바꿨지만 Run하지 않은 상태에서 결과가 이전 값임을 구분할 수 있는지 확인한다.

| 회귀 테스트 | 각 검증 사례를 자동화된 단위 테스트로 추가하고 CI에서 실행. |


### 5. AI에게 요구할 산출물
- 관련 파일 경로와 함수명을 포함한 코드 추적표.
- 화면 관찰 사실 / 코드로 확인된 사실 / 아직 확인하지 못한 가설을 분리한 결과표.
- 각 계산 항목의 공식, 단위, 복리·할인 관례, 가정 및 독립 계산 비교표.
- 실행 가능한 테스트 코드와 테스트 실행 로그(통과/실패/미실행을 구분).
- 발견한 버그별 재현 절차, 원인, 영향 범위, 최소 수정안 및 회귀 테스트.
- 수정 전후 동일 입력 비교와 성능 측정값.
- 외부 데이터 키가 필요한 경우 키를 코드·로그·보고서에 노출하지 말고, 키 없이 가능한 테스트를 우선 수행.

### 6. AI에 그대로 입력할 지시문
너는 QUANTGEN의 독립적인 금융공학 코드 감사자이자 테스트 엔지니어다. 첨부된 ‘QUANTGEN Bonds 화면 테스트 기반 구현 검증 및 수정 요청서’를 요구사항으로 사용하라. 먼저 저장소에서 Bonds UI가 호출하는 실제 계산 함수와 데이터 경로를 추적하고, 요청서의 각 항목을 ‘코드로 확인됨 / 테스트로 확인됨 / 미확인’으로 분류하라. 화면에 표시된 숫자를 정답으로 가정하지 말고, 독립적인 계산이나 별도 구현으로 가격·YTM·듀레이션·컨벡서티·DV01·z-spread·carry/roll·시나리오 P&L·Treasury futures hedge를 재현하라. Price와 YTM 입력 충돌 오류는 빈 값, 0, NaN/Inf, 음수 등 경계 사례를 포함해 원인을 찾고 테스트하라. 시나리오에서는 각 곡선 변화, 할인인자, 재평가 가격, 손익 환산식을 기록하라. 실제 FRED와 synthetic fallback은 반드시 구분하라. 결과를 내기 전에 관련 자동 테스트를 실행하고, 실행하지 못한 테스트는 통과로 표시하지 마라. 버그를 발견하면 최소 수정과 회귀 테스트를 제안하고, 실제로 코드를 변경했다면 변경 파일·diff 요약·테스트 결과를 보고하라. 실거래·시장 정확성이 검증되지 않은 기능을 검증 완료라고 표현하지 마라. 최종 보고서는 ① 요약 ② 심각도별 이슈 ③ 재현 단계 ④ 수식 및 독립 계산 ⑤ 수정안 ⑥ 테스트 로그 ⑦ 남은 리스크 순서로 작성하라.

### 7. 주의사항
이 문서는 제공된 화면 캡처에서 읽을 수 있는 값과 그에 대한 검증 요청을 정리한 것이다. 화면만으로는 내부 구현, 계산 정확성, 실제 FRED 데이터 적합성, 전체 애플리케이션 성능을 확정할 수 없다. 따라서 이 문서를 근거로 곧바로 금융 계산 오류가 있다고 단정하지 말고, 검증 절차와 증거를 요구해야 한다.
