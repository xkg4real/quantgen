## Q-SCORE v0.1의 의미와 한계

기존 `compute_signals`의 기술신호 합성값과 `analyze_history`의 과거 위험 통계를 재사용하는 **새 실험적 표시 점수**입니다. 기존 정규 신호의 비중·연구 승인·주문 판단을 변경하지 않습니다. 기업 펀더멘털 평가, 신용/투자 등급, 고객 만족 평점, 모든 분석 엔진의 종합 인증 또는 상승·수익 확률이 아닙니다.

`clip`은 0–100으로 제한하는 함수입니다. 비율은 소수 단위입니다.

```text
기술신호 점수 = clip((기존 합성값 + 100) / 2)
낙폭 점수     = clip(100 × (1 − abs(과거 최대낙폭) / 0.40))
꼬리손실 점수 = clip(100 × (1 − max(0, 일간 95% CVaR) / 0.08))
Q-SCORE      = round(기술신호 × 0.70 + 낙폭 × 0.15 + 꼬리손실 × 0.15, 2)
별점         = 1 / 2 / 3 / 4 / 5개 (20 / 40 / 60 / 80점 경계)
```

기존 기술신호 내부 구성은 SMA50·SMA200·모멘텀 각20%, RSI·MACD 각15%, 변동성10%입니다. 새 점수의 70/15/15 비중, 낙폭40%·CVaR8% 기준, 별점 경계는 초기 설계값입니다. 학습·교차검증·수익률 실험으로 최적성이나 예측력을 입증하지 않았습니다.

계산은 KIS 국내주식의 수정 일별 이력 최소200개·최근 최대252개를 요구합니다. 이력 부족·평탄한 표본·비정상 값·7일 넘게 오래된 마지막 이력·잘못된 수정 기준에는 정상 별점을 부여하지 않습니다. 유효한 실제 체결은 당일 잠정 종가를 바꾸며, tick마다 새로운 일별 관측을 추가하지 않습니다. 원시 차트는 이 과정으로 수정하지 않습니다. 체결 시각이 없거나 역순·너무 오래됨·미래인 경우, 최근 수정 종가 대비 가격 비율이 0.65–1.35를 벗어나 같은 가격 기준임을 보수적으로 확인할 수 없는 경우도 거부합니다. 이 범위 검사는 기업행사 조정의 완전한 검증이 아닙니다.

Home 체결 수용은 최대60초, 점수 제어·순수 계산은 최대120초의 신선도 경계를 별도로 사용하고 미래 허용은5초입니다. Home의 개별 종목에서 수신이15초 넘게 없으면 해당 행을 stale로 바꾸고, 수신 제어기 역시15초 넘는 전체 공백을 stale로 표시하므로 점수 계산의120초 허용을 “120초까지 정상 연속 실시간”이라는 표시 보증으로 사용하지 않습니다. Home 가격 표시는200ms 주기로 변경된 행을 모아 다시 그립니다. 점수용 새 체결은 제어기에서 종목별 최신값으로 모아 최대1초 주기로 계산합니다. 수정 이력 캐시는 제어기별 최대16종이며 Home·차트는 별도 제어기를 사용합니다.

근거: [순수 계산과 한영 도움말](../../core/research/qscore.py), [제어·갱신](../../quantgen_desktop/qscore.py), [Home 체결 검사](../../quantgen_desktop/watchlist_live.py). 기존 데이터 공급사의 권리·호출 한도·국외이전·보유기간 검토는 이 산식 설명으로 완료되지 않습니다.

## 실행과 연결 진단

이번 UI는 `python -m quantgen_desktop`으로 실행하는 PyQt6 네이티브 앱입니다. 기존 `python main.py`는 Flet 진입점으로 유지하므로 같은 변경 화면을 확인하는 실행법으로 혼동하지 않습니다. Windows 가상환경이 준비되어 있다면 저장소 루트에서 PowerShell 명령 `& .\.venv\Scripts\python.exe -X utf8 -m quantgen_desktop`으로 해당 환경을 명시합니다. 가상환경이 없거나 이전 체크아웃을 실행한 경우에는 최신 소스·의존성 준비를 먼저 완료해야 합니다.

KIS 키가 없으면 차트 오류에 저장소의 `.env`에서 `KIS_APP_KEY`·`KIS_APP_SECRET`을 설정한 뒤 다시 실행하고 시스템의 데이터 연결에서 존재 여부를 확인하라는 안내를 표시합니다. 키를 공개 이슈·대화·Git에 제출하는 방식이 아니며 이 오류가 네트워크 연결·구독 성공을 뜻하지 않습니다. 주 작업자가 확인한 사용자 Windows 로그/화면은 이전 소스에서 KIS UI가 없었다가 업데이트 후 차트가 표시되고 `KISUnavailable`을 만난 단계까지입니다. 실제 키를 입력한 후의 체결 수신 증거는 아직 없습니다.

- **구현 회귀 검사:** `qscore_acceptance.py`, `desktop_qscore_acceptance.py`, `watchlist_live_acceptance.py`, `home_watchlist_acceptance.py`, `desktop_watchlist_acceptance.py`, `desktop_home_live_acceptance.py`, `desktop_market_layout_acceptance.py`가 계산·주입 시세·Qt 표시·생명주기·레이아웃을 다룹니다. `runtime-smoke.yml`의 기존 KIS 검사 단계에 이 모듈을 연결한 차이를 대조했습니다. 최종 통합 실행 결과는 주 작업자의 모듈별 실행 기록으로 확인하며 중복 실행 수를 서로 합산하지 않습니다. 검사 존재나 CI 설정 자체를 실행 통과로 기록하지 않습니다.
- **미확인:** 실제 사용자 KIS 키·계약·거래시간대의 6종 수신, 새 통합 변경의 Windows 실행·화면 확대·전체 키보드/스크린리더, 공급사 상업 표시·파생 자료 이용권, 점수 예측 성능, 운영 로그/백업·공유 서버 분리, Flet 동등 UI·소개사이트 AWS 배포입니다. 위 기존 차트 화면 확인과 새 통합 변경의 전체 검증을 구분합니다.
- **정합성 기준선:** 정책 검토 후에도 소스가 바뀌는 동안 `source-review.json`을 임의 갱신하지 않았습니다. 주 작업자의 코드 고정 통지 후 차트 첫 연결·200ms 표 갱신·종목별 stale·신규 회귀검사·워크플로의 추가 차이를 대조한 뒤 검토자 `Codex UI session 2026-11-02`와 이 기록을 참조하는 메모로 갱신했습니다. 이후 코드가 바뀌면 관련 사실을 다시 대조하고 기준선을 갱신해야 합니다. 정합성 통과와 공개 준비 `BLOCKED`는 동시에 성립할 수 있습니다.
