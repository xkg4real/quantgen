## 2. 판독 날의 시작 (5분)

### 2.1 시각과 UTC 날짜 확인

```powershell
"PC time: " + (Get-Date -Format "yyyy-MM-dd HH:mm") + "   UTC date: " + (Get-Date).ToUniversalTime().ToString("yyyy-MM-dd")
```

- 기대: PC 시각이 KST 09:30 이후입니다. UTC 날짜를 적어 둡니다. 판독은 이 UTC 날짜 안에서 끝냅니다(준비 3.0).
- 이유: 스냅샷 이름이 UTC 날짜입니다. 같은 UTC 날짜에 다시 돌리면 저장된 스냅샷을 다시 읽고, 날짜가 바뀌면 새로 받습니다(`paper_live/replay.py:147`, `paper_live/engine.py:170-175`).
- 전원을 연결하고 절전을 끕니다. 이 PowerShell 창은 끝까지 닫지 않습니다. 환경 변수와 기록(transcript)이 이 창에 묶여 있습니다.
- PowerShell은 일반 권한으로 엽니다. venv는 활성화(`Activate.ps1`)하지 않고 python.exe를 전체 경로로 부릅니다. 그래서 실행 정책을 바꿀 필요가 없습니다.

### 2.2 같이 도는 것이 없는지 확인

```powershell
Get-CimInstance Win32_Process | Where-Object { $_.Name -match '^(python|pythonw|py|flet)' } | Select-Object ProcessId, Name, ExecutablePath, CommandLine | Format-List
```

- 기대: 아무것도 나오지 않습니다. 줄이 나오면 CommandLine과 ExecutablePath를 봅니다. `nautilus`, `run_all`, `main.py`, `paper_live`, `quantgen` 중 하나라도 있으면 멈춥니다(대소문자 무관). 무엇인지 모르면 멈춥니다. CommandLine에는 작업 폴더가 나오지 않습니다. 그래서 QUANTGEN이라는 글자가 없다고 안전한 것은 아닙니다.
- 그런 줄이 있으면: 테스트 스위트나 다른 실행이면 끝날 때까지 기다립니다. QUANTGEN 앱이면 닫습니다. 무엇인지 모르면 멈추고 그 줄을 Claude에게 보냅니다.
- 근거: 파일럿과 판독은 겹치지 않습니다(Nautilus 스펙 3.8, GOVERNANCE-9). 스위트와 판독을 겹치지 않는 것은 T-HERM-02에서 끌어낸 추정입니다(준비 6.3). 앱은 근거 문서가 없는 제안입니다(준비 3.1).

- 선택: 다섯 낱말 중 하나가 든 줄만 따로 보려면 아래 명령을 돌립니다. 위 명령을 대신하지 않습니다. 위 명령에 무엇인지 모르는 줄이 있었으면 이 명령에 아무것도 나오지 않아도 멈춥니다.

```powershell
Get-CimInstance Win32_Process | Where-Object { $_.Name -match '^(python|pythonw|py|flet)' } | Where-Object { "$($_.ExecutablePath) $($_.CommandLine)" -match 'nautilus|run_all|main\.py|paper_live|quantgen' } | Select-Object ProcessId, Name, ExecutablePath, CommandLine | Format-List
```

## 9. 재실행 규칙과 멈춤 신호

### 9.1 재실행 규칙 (H-D4, 원문)

`H-D4 = (가) WARNING 줄이 나오면 바로 Ctrl+C. 날짜 줄이 나오기 전에 멈춘 경우만 같은 UTC 날짜에 최대 2번 더. 날짜 줄이 나왔으면 다시 돌리지 않음 [권고]`

이 표의 적용:

1. WARNING 줄이 나오면 바로 Ctrl+C를 누릅니다. `KeyboardInterrupt` 줄이 나오는 것은 정상입니다.
   - 재생 중에는 창을 클릭하거나 글자를 선택하지 않습니다. 선택 영역이 있으면 Ctrl+C가 복사가 됩니다. 선택이 보이면 먼저 Esc를 누르고 바로 Ctrl+C를 누릅니다.
2. 날짜 줄(`2026-10-21 {...}`)이 하나도 나오기 전에 멈췄으면:
   - 2.1의 명령으로 UTC 날짜가 같은지 봅니다.
   - 같으면 그 프로필의 재생 블록(7.2 또는 8.1)만 다시 돌립니다. 판정은 돌리지 않습니다.
   - 한 프로필에 처음 1번과 다시 2번, 모두 3번까지입니다 `[확인 필요 #6]`.
   - WARNING 실행은 스냅샷을 저장하지 않아 다시 돌리면 새로 받습니다(`paper_live/engine.py:181-186`).
3. 3번 모두 WARNING이면 멈추고 보고합니다(준비 D-4 ①).
4. 날짜 줄이 이미 나왔으면 그 실행은 본 것으로 칩니다. 다시 돌리지 않습니다. 판정도 돌리지 않고 멈추고 보고합니다.
5. UTC 날짜가 바뀌었으면 다시 돌리지 않고 멈추고 보고합니다.
6. WARNING 뒤 날짜 줄 전에 `KeyError`로 멈춘 경우도 날짜 줄 전에 멈춘 경우로 봅니다. 빠진 종목이 기준 종목이면 이렇게 멈출 수 있습니다(준비 3.6).
