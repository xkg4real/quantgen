# QUANTGEN 인수인계 브랜치 (`handoff`)

이 브랜치에는 코드가 없습니다. 작업 중인 에이전트(주로 Claude)가 지금 상태를 여기에
기록하고, 그 에이전트가 멈추면 다른 에이전트(주로 GPT)가 이 기록을 읽고 이어서
작업합니다. 코드 작업은 각자의 작업 브랜치에서 하고, 이 브랜치에는 인수인계 문서만
올립니다. 그래서 `main`에 PR을 합칠 필요 없이 바로 push할 수 있습니다.

## 파일

|---|---|---|

| `TEMPLATE.md` | `CURRENT.md`의 양식 | 양식을 바꿀 때만 수정 |
| `AGENTS.md` | GPT(와 다른 에이전트)가 이 브랜치를 읽는 규칙 | 사람 |
| `UI_SESSION_CURRENT.md` | 화면(UI) 작업의 소유자 결정과 진행 기록. 맨 위 "소유자 결정" 블록(UI-D1~D4: UI 기준 앱 = 네이티브 PyQt)은 화면 작업을 하는 모든 에이전트가 먼저 읽고 따릅니다(`AGENTS.md` 6절). | UI 작업을 맡은 에이전트 |

| `AUTO_STATE.patch` | `patch_base`(원격에 있는 커밋)부터 스냅샷 시점의 작업 트리까지의 diff. 푸시 안 된 커밋과 커밋 안 된 변경(추적 중인 파일만)이 함께 들어 있습니다. | 같은 스크립트 |

## 운영 방식 — 사용자 지시로 인계

## 소유자 최신 지시 — 자동감시 취소·수동 인계 (2026-11-13T22:03:26+09:00)

**메인·연구·UI·웹사이트의 GPT/Claude 세션 공통:** 상시 관찰·매시간 감시·자동 인수는 취소됐다. 각자 사용량/실행 한도에 가까워지거나 세션을 끝내기 전에 인계문서를 남기고, 사용자가 인계를 읽고 이어받으라고 지시할 때 진행한다. 기존 직접 요청으로 진행 중인 작업의 범위는 유지한다. 이전의 주간 자동감시 일정·stale 상태만으로 재개하지 않는다.

[전체 운영 지시와 인계 항목](OWNER_HANDOFF_POLICY_2026-11-13.md). 감시 예약은 비활성 확인 완료. 이 공지는 공용 문서 전달이며 개별 채팅의 수신/열람 확인이 아니다. 아래 작업 상태·소유권·완료 기록은 그대로 보존한다.

상태값은 진행·소유권을 설명하며 자동 실행 신호로 사용하지 않습니다.

| status | 의미 | 사용자 인수 지시가 있을 때 |
|---|---|---|
| idle | 진행 중인 작업 없음 | 새로 지정된 범위 확인 |
| checkpoint | 작업 중 중간 저장 | 담당자와 변경 상태 확인; 자동 선점 금지 |
| handoff | 작업을 멈추며 인계 저장 | 근거·범위·소유권 확인 후 인수 |
| taken | 특정 실행이 작업 중 | 타 실행 선점 금지 |
| returned | 작업을 끝내거나 멈추고 반환 | 완료/미완료를 읽고 요청된 범위에서 이어감 |

이전 목요일 매시간 확인·화요일 고정 반환 및 stale 자동 인수 일정은 소유자가 2026-11-13에 취소했습니다. 날짜·사용량 리필·rate_limit_error만으로 감시나 개발을 자동 재개하지 않습니다. AUTO_STATE는 같은 source_branch의 복구 참고 자료로만 사용하며 자동 인수 근거가 아닙니다. 예약을 다시 켜려면 별도의 명시적 사용자 지시가 필요합니다.

GPT와 Claude는 작업 단위마다 복구 가능한 checkpoint를 남기고 한도 징후/세션 종료 전에 상세 인계를 저장합니다. 사용량을 알 수 없으면 추정하지 않습니다. 다음 담당은 사용자가 인계를 읽고 이어받으라고 지시하면 진행합니다. 기존에 맡긴 작업과 제품 CI·웹 배포 파이프라인은 이번 자동감시 취소와 구분합니다.

## 작업 ID와 완료 기록

- 작업 ID는 `docs/nautilus_bridge/REMAINING_WORK_*.md`(최신 날짜)의 순서 표기(`③-1`, `③-2` 등)를 씁니다.
  한 항목을 나눠서 끝내면 `③-2/a`, `③-2/b`처럼 씁니다. ID는 꾸밈 없이 씁니다(백틱, 굵게 표시 없이,
  하이픈은 키보드의 `-`).
- `CURRENT.md`의 `done_ids`에는 끝낸 ID, `next_ids`에는 남은 ID를 쉼표로 구분해 적습니다.
  `next_ids`에는 `LEDGER.md`에 이미 있는 ID를 넣지 않습니다.
- 작업을 시작하기 전에 `LEDGER.md`에서 그 ID와 바뀐 파일을 찾아봅니다. 이미 있으면 다시 하지 않습니다.

## 흐름

1. 현재 담당 GPT/Claude가 요청받은 작업을 진행하며 checkpoint를 남깁니다.
2. 한도 징후나 세션 종료 전에 완료·미완료·검증·커밋·다음 작업을 인계문서에 저장합니다.
3. 사용자가 다음 담당에게 인계문서를 읽고 이어받으라고 지시합니다.
4. 다음 담당이 최신 문서·실제 소유권·완료 기록을 확인하고 CAS/read-back 후 지정 범위에서 진행합니다.

## 규칙 요약

- `CURRENT.md`는 덮어쓰기 방식입니다. 이전 내용은 git 기록에 남습니다. 새 작업으로
  바꿀 때만 기존 문서를 `archive/YYYY-MM-DD-HHMM-<작업명>.md`로 옮깁니다.
- 시각은 모두 한국 시간(+09:00)의 ISO 8601로 적습니다. 예: `2026-10-28T21:30:00+09:00`
- 비밀 값(API 키, 토큰, 계좌번호)은 절대 적지 않습니다. `.env`의 변수 이름만 적습니다.
- 커밋 메시지는 `handoff: <status> <작업명>` 형식으로 씁니다.
- 앞부분(front matter)은 `key: value` 한 줄씩 씁니다. 값에 따옴표를 붙이거나 줄을 들여쓰지
  않습니다. 읽을 수 없는 `CURRENT.md`는 잠긴 것으로 취급되어, 다른 에이전트가 손대지 못합니다.
